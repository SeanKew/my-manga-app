# MNN + Qwen on Android (Manga.app integration scaffold)

This directory is a **standalone Android library project**, kept separate from Manga.app's Python/Flet source. The current app is built with Flet; placing Kotlin/JNI files in the Python package alone does not expose them to the Flet UI. A Flutter/Flet platform bridge is still required before app screens can call this library.

## Layout

```text
native/mnn-llm/
├── settings.gradle.kts
├── build.gradle.kts
└── mnn-llm/
    ├── build.gradle.kts
    └── src/main/
        ├── AndroidManifest.xml
        ├── cpp/
        │   ├── CMakeLists.txt
        │   ├── llm_jni.cpp
        │   └── include/llm/llm.hpp
        ├── java/com/seankew/mnnllm/MnnLlm.kt
        └── jniLibs/arm64-v8a/
            ├── libMNN.so
            ├── libMNN_Express.so
            ├── libllm.so
            └── libmnn_llm_jni.so (built by CMake)
```

## 1. Build MNN for Android

Use the MNN source revision whose `llm.hpp` matches the JNI code. Build the arm64 Android libraries with LLM support enabled. MNN's LLM API changes between revisions, so verify `response`, `generate`, `stoped`, `getContext`, and `destroy` against that exact header before building.

Copy the resulting `libMNN.so`, `libMNN_Express.so`, and `libllm.so` to `mnn-llm/src/main/jniLibs/arm64-v8a/`. Copy the matching public MNN headers to `mnn-llm/src/main/cpp/include/MNN/` and the matching `llm.hpp` to `mnn-llm/src/main/cpp/include/llm/llm.hpp`.

The binary libraries and headers are intentionally not committed here. They are generated from the selected MNN revision and are platform-specific.

## 2. Obtain the model

Use a Qwen2.5-1.5B-Instruct model converted for MNN, with the model files expected by the selected MNN release, typically `config.json`, `llm_config.json`, `llm.mnn`, `llm.mnn.weight`, and `tokenizer.txt`.

Do not bundle the model weights in the APK. Put them in app-private files storage, for example:

```text
<app-private-files>/models/Qwen2.5-1.5B-Instruct-MNN/
```

Check available storage and memory before loading; actual RAM use depends on the conversion, context length, runtime, and device.

## 3. Build the library

Open `native/mnn-llm` as a standalone Gradle project in Android Studio, or build it with a compatible Gradle installation:

```bash
gradle :mnn-llm:assembleDebug
```

Use JDK 17, Android SDK 35, NDK, and CMake 3.22.1 or compatible versions. This command cannot succeed until the matching MNN shared libraries and headers have been copied into the paths above.

## 4. Connect it to Manga.app

Manga.app currently uses Python/Flet and its APK is generated by `flet build apk`; it does not currently contain a checked-in native Android Gradle app module. The next integration step is a custom Flutter/Flet platform bridge that exposes model status, load, streaming chat, stop, and release to the Python UI. The bridge must also copy/manage model files in private storage and dispatch blocking native calls away from the UI thread.

## Important compatibility notes

- JNI symbols and the Kotlin package must match exactly: `com.seankew.mnnllm.MnnLlm`.
- Keep all model load/generate/release operations serialized. Stop must be safe to call while generation is running.
- Verify streaming output against the selected MNN API: some releases differ in how `response()` and `generate()` write to the output stream.
- This scaffold is not evidence of a successful APK build or on-device inference. Test with a real arm64 Android device after supplying the matching MNN binaries and headers.
